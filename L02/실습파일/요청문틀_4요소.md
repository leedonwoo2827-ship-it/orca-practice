# 요청문 틀: 4요소 (2강 실습용)

에이전트나 봇에게 일을 맡길 때 아래 네 칸을 채운다. 칸이 비어 있으면 에이전트가 짐작으로 채운다.

```text
[목적] 이 결과물을 누가, 어디에 쓰는가
- 

[자료] 읽어야 할 파일 (파일 이름 정확히)
- 

[형식] 만들 파일 이름, 분량, 말투, 구성
- 

[검토 기준] 결과가 통과하려면 지켜야 할 것
- 자료에 없는 내용은 지어내지 말고 "확인 필요"로 표시한다
- 
```

## 칸별 질문

| 요소 | 스스로 물어볼 질문 | 빠지면 생기는 일 |
|---|---|---|
| 목적 | 읽는 사람은 누구인가? 이걸 받고 무엇을 하게 되는가? | 말투와 분량이 엉뚱해진다 |
| 자료 | 에이전트가 읽을 파일이 폴더에 있는가? 이름이 정확한가? | 그럴듯한 내용을 지어낸다 |
| 형식 | 파일 이름, 길이, 표/목록, 말투를 정했는가? | 매번 다른 모양으로 나와 다시 고친다 |
| 검토 기준 | 무엇을 보면 "통과"라고 할 수 있는가? | 결과를 감으로 검토하게 된다 |

## 나쁜 요청 → 좋은 요청 예

| 나쁜 요청 | 무엇이 빠졌나 |
|---|---|
| "온보딩 메일 써 줘" | 목적(누구에게), 자료(어느 메모), 형식(파일·분량), 검토 기준(미정 사항 처리) 모두 |
| "이거 요약해 줘" | 무엇을, 누구를 위해, 몇 줄로 |
| "보고서 좀 잘 써 줘" | "잘"의 기준 |
